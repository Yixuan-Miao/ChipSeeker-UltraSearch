# Circuit review and research-topic selection

Search objective and admission policy are independent. Use `broad_discovery` by default for both coverage and ordinary precision: no implicit date, publisher, publication-type or measurement restriction. For a precision shortlist, select only the closest matches within the agreed topic. In a broad historical survey set a wide retrieval interval explicitly.

Select `circuit_review` only for a requested formal circuit review, and confirm or explicitly override its defaults: the preceding ten years, a preference for IEEE, formal journal and proceedings articles, and the target circuit as the main contribution. "Precise" or "top ten" alone does not select this profile. Both profiles honor explicit `years: [START, END]`, `start_date`/`end_date`, `allowed_publishers` and `allowed_publication_types`. A hard source limit uses `allowed_publishers`, not `preferred_publishers`. Set display limits independently of discovery depth; split a deliberately broad review into branches or reports instead of silently truncating coverage at 200.

## Evidence before admission

Use schema `ultrasearch-screened-papers/v2` and a `review_policy` object in the curated `papers.json`. The renderer applies `review_policy.apply_review_policy` and saves the resolved policy, independent readability/source labels, decisions and exclusions in `report-data.json`. Legacy v1 reports remain readable; adopt v2 when re-screening them. Carry `manual_exclusions` and `screening_audit` from the previous structured report when refreshing. Use `record_manual_exclusion` to save an explicit exclusion before removing a publication. It propagates through verified version relationships, including when the old seed is absent.

Focused candidates need `review_evidence` with `contribution`, `relevance`, `publication_type`, `publisher`, `measured_target`, `readability`, source `evidence` and `publication_evidence`. In broad discovery capture available evidence without imposing the focused eligibility checks. Evidence entries require `url`, `location` and `text`. Record what the source establishes. Typical contribution values are `target_circuit`, `system`, `supporting_module` and `unknown`; relevance is `strong`, `weak` or `unknown`. Publication types include `journal-article` and `proceedings-article`. Unknown fields remain unknown. Record formal issue year separately from online date. Never derive publication year from the DOI suffix.

When the user asks for the target circuit to be the contribution, distinguish it from a supporting module in an ADC, DAC, SoC or link. For a requested measurement constraint, check whether the measurement concerns that circuit or the surrounding system. In ordinary discovery a clear source abstract can establish relevance without full-text or measurement verification. Under the formal `circuit_review` profile, nonpreferred publishers require an explicit `exception_reason`, strong relevance and measured target-circuit evidence.

### Evidence for hard constraints

Use `review_policy.requirements` for objective criteria. Example: `{"id":"speed","metric":"sample_rate","subject":"aggregate_adc","basis":"author_measured","unit":"GS/s","min":8}`. Save one or more facts in `review_evidence.observations.speed`: `{"metric":"sample_rate","subject":"aggregate_adc","basis":"author_measured","unit":"MS/s","value":8000,"evidence":[{"url":"…","location":"Measurement results, Fig. 5","text":"…"}]}`. For categorical constraints use `equals` instead of a unit/bound. Keep the same identifiers across the policy and facts. Do not use the target criterion as the observed value.

- A cryogenic amplifier's operating temperature, a system-stage temperature and equivalent input noise temperature are different metrics/subjects. A system or room-temperature result cannot satisfy a target-amplifier cryogenic measurement constraint.
- For ADC/SerDes distinguish aggregate vs channel, sample vs symbol vs bit rate, and input frequency. A value cited in a comparison is not author-measured. For CTLE, record whether the new design is the equalizer or the whole chain using one.
- For OTA/TIA/op-amp, use function as well as acronyms. A receiver may qualify if its target block is the main contribution and separately measured; the presence of a block in a DAC or link is not enough.

A compatible fact below a hard bound does not qualify; missing, unauthenticated, comparison-only or incompatible facts stay pending. Save what was reviewed and the source location. Scope and architecture judgments remain the agent's job.

## Targeted external gap checks

`review_policy.plan_gap_checks` produces bounded tasks from sparse branches, missing formal specialist sources and reference leads. `record_gap_check` saves receipts with source, outcome, source evidence and query IDs; reuse completed receipts. Record failed requests, pending work, unavailable external sources, truncated returns and no visible indexed identity separately. An unfilled page says nothing about papers outside the visible index.

### Run the follow-up from a normal workspace

1. Collect initial queries and save the initial `papers.json` plus `research_branches`, `source_checks` and/or `reference_leads` as applicable. Put `max_api_requests` in `queries.json` when there is a user-approved query limit; the collector rejects a larger plan before submitting. Leave room for hydration. An optional `max_external_checks` caps recorded external tasks across rounds; it counts source checks, not every web request within them.
2. Run `python OUTPUT review-next --workspace WORKSPACE`. Use branch `query_ids`, `priority` (larger is more useful), `qualified_count`, optional `partition_by` and `partition_cost` (new requests, default 1) to choose follow-ups. Set `qualified_gain: 0` only when a tried split added no eligible evidence, or `resolved: true` if the branch is covered. Do not loop through low-yield variants.
3. Run selected partitions by appending justified query IDs to the same plan/checkpoints; retry original IDs rather than resubmitting. Use available external tools for selected external checks. For each, pass `--receipt FILE` to `review-next`; JSON fields: `cache_key`, `status`, source `evidence`, optional `query_ids`, `discoveries` (verified formal records), and `version_relations` (both records and explicit source evidence). An external miss needs a source/location; access failures are not misses. `index_no_records` never closes the external check. A verified institutional publication record needs the formal venue, DOI and clear bibliographic evidence, not merely a hosted preprint.
4. Review `screening_candidates` and newly retrieved partition candidates. Move reviewed candidates (including ones submitted to policy audit) into `papers.json` with evidence. If explicitly rejecting a discovery outside that list, preserve the reason in `screening_decisions` and add its DOI to `gap_screened_dois`. Do not just mark papers screened to hide unresolved leads. Run `review-next` again, then render. Report the most consequential gaps in prose; keep full receipts, outcomes and discovery paths in the data folder.

Library-only runs save external work as skipped without executing it. `budget_exhausted`, `not_run`, `source_unavailable` and transport interruption remain distinct. To rank by the saved evidence and scope before venue, set `rank_by_evidence: true` (typed requirements already enable it). Judge a source's value by unique works retained after screening across different runs, not how often the same DOI appeared; stable specialist value is a suggestion for future corpus review, not permission to auto-import.

For a missing specialist venue, inspect configuration and enabled source, fetched issue/online records, admission, normalization, keyword and semantic visibility, response, merge and report stages independently. Check full names, aliases and ISSNs. A display alias does not establish an enabled source. A preprint with a journal DOI does not establish formal issue import. Try unrestricted DOI and independently verified full title, batch identity checks and retain the request IDs. Preserve raw source versions when a formal record enriches a preprint with the same DOI. Split capped discovery queries by year, venue or technical branch; investigate useful partitions within budget. Do not increase the default result cap.

Use the customer's available web tools for publisher records, official proceedings, DOI registration, institutions or public author manuscripts. Follow a bounded number of references, citations and author leads from strong seed designs. A benchmark table or thesis reference can expose a mechanism absent from initial keywords. `work_versions.discover_reference_gaps` replays title-based reference discovery against a verified catalog without injecting the missing DOI. An inaccessible source remains an unresolved task. A known coverage policy can justify external checking without changing the server's collection rules.

## Formal publication versions

Keep publication identity and research relationships independent. `query_family` groups retrieval angles. DOI-based merging preserves one publication record and its original `publication_sources`. Different conference and journal DOIs remain different publications.

When requested or when a likely duplicate would affect the list, inspect both conference-to-journal and journal-to-conference paths. Record `version_relations` with `from_doi`, `to_doi`, `relation_type`, `status` and source evidence containing `kind`, `url`, `location` and `note`. Supported confirmed relationships include `journal_extension`, `conference_version` and `shared_design`. Strong evidence kinds are `publisher_version_statement`, `author_version_statement` and `explicit_design_reuse`. Also save each formal record's `publication_status` and `publication_evidence` with a publisher, official-proceedings or DOI-registration URL. Similar authors, process, circuit, frequency or mutual citations establish leads only.

`expand_verified_versions` follows this bounded reviewed catalog from either seed direction. `group_work_versions` confirms groups only with formal records and explicit evidence. The renderer shows one journal-first work row with directly adjacent conference metadata and links. Venue labels come from each publication record. Save per-version measurements and conditions on that version. Only set `attach_out_of_scope_versions: true` when the user explicitly wants verified associated publications outside the main date/source policy as labeled attachments. Preserve manual exclusions.

Describe `not_verified` and `demonstration_without_publication` separately in the relation audit. The former is unresolved research; the latter requires evidence that the presentation has no independent publication record. Avoid inventing a conference name from memory. `report-data.json`, Markdown and offline HTML share the same works and relationships; `publications.ris` exports both original formal DOIs as separate entries.
